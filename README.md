# Студенческий помощник

[![Tests](https://github.com/CaptainReinor/doklad-bot/actions/workflows/tests.yml/badge.svg)](https://github.com/CaptainReinor/doklad-bot/actions/workflows/tests.yml)

Исправленная версия Telegram-бота и мини-приложения. При первом запуске база обновляется автоматически; перед переходом со старой схемы создаётся `schedule.db.before-v2.bak`.

## Что работает

- Новый пользователь по `/start` открывает приложение и сразу попадает на регистрацию в «Кабинете». Команда `/register` оставлена как запасная регистрация сообщениями.
- Темы докладов назначаются конкретной группе или обеим группам. Для темы можно разрешить нескольких выступающих. Общая тема с несколькими выступающими закрепляется за группой первого записавшегося; участники другой группы присоединиться не могут.
- Отмена собственной брони студентом и снятие любой брони администратором. При смене группы перенос броней проверяется на конфликты.
- Управление темами из кабинета администратора: добавление, выбор предмета из расписания, сроки заданий и докладов, переименование, архив, восстановление и удаление незабронированных тем. Студенты фильтруют темы по предметам; длинные названия показаны сокращённо.
- Управление расписанием из кабинета администратора: добавление, редактирование, архив, восстановление и удаление занятий. К занятию можно добавить необязательную HTTPS-ссылку; только тогда студент видит кнопку подключения.
- Три независимые настройки уведомлений: домашка, темы докладов и изменения расписания.
- Новые темы собираются в одну подборку через минуту после последнего добавления; редактирование тем, сроков и броней не создаёт рассылку. Напоминания о сроках приходят за календарный день по московскому времени.
- Исходные данные мини-приложения: 44 занятия и 10 тем. По умолчанию показаны сегодняшние и будущие занятия, начиная с ближайшего; прошедшие даты вынесены в отдельный раздел.
- Экспорт текущего фильтра расписания в PDF и своих тем в текстовый файл.

Бронирования и профиль загружаются с сервера. Открытое приложение обновляет данные примерно раз в 5 секунд и при возвращении в окно. Если ответ сервера не получен, приложение не подтверждает успех бронирования.
Telegram SDK и модуль PDF хранятся рядом с приложением, поэтому недоступность стороннего CDN не оставляет мобильный Telegram на пустом экране загрузки. Для оформления используются системные шрифты устройства.

## Обновление через Docker Desktop

После одноразовой настройки обновления отправляются на VPS без ручного входа в его терминал. Docker Desktop передаёт исходники по SSH, собирает образ непосредственно на сервере, запускает контейнер и проверяет `/health`. База хранится в `/opt/telegram-bot/docker-data` вне контейнера. Перед первым переключением создаётся резервная копия; при неудачном последующем обновлении `deploy.cmd` возвращает предыдущий образ.

1. Запустите Docker Desktop.
2. Один раз откройте `setup-server.cmd`. Он создаст SSH-ключ, попросит пароль VPS, установит Docker на сервер, сохранит базу и переключит службу на контейнер.
3. Для следующих обновлений запускайте `deploy.cmd` двойным щелчком.
4. После подключения GitHub запускайте `publish-and-deploy.cmd`: он сохраняет изменения в Git, отправляет их в репозиторий и только после успешной отправки обновляет VPS.

Токен и база не входят в Docker-образ и Git. Контейнер читает прежний `config.py` с сервера и подключает постоянный каталог данных. Nginx и Cloudflare Worker продолжают использовать тот же локальный порт `127.0.0.1:8080`.

## Быстрый запуск на Windows

Требуется Python 3.11 или новее. Проверено на Python 3.12.13.

Распакуйте архив в отдельную папку, откройте в ней PowerShell и выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

Если команда `py` отсутствует, используйте установленный `python`. Активация окружения не требуется.

`run.py` запускает сервер и бота вместе. По умолчанию локальная страница доступна по адресу `http://127.0.0.1:8080/`. В обычном браузере доступен просмотр расписания. Для работы с профилем и бронями приложение нужно открывать через кнопку бота в Telegram. Запросы к Telegram используют IPv4; временная недоступность Telegram не останавливает веб-приложение.

При первом запуске в Telegram отправьте `/start`, откройте приложение и заполните форму в «Кабинете». Данные уже зарегистрированных пользователей будут прочитаны из базы.

## Подключение к Telegram

Мини-приложению нужен доступный HTTPS-адрес серверной части. В исходном проекте указан GitHub Pages; один статический сайт не обеспечивает общий список броней.

### Вариант 1: страница и сервер на одном адресе

Разместите Python-проект на сервере и настройте HTTPS-прокси до его локального порта. Прокси должен передавать исходный заголовок `Host`. Перед запуском задайте адрес страницы:

```powershell
$env:WEB_APP_URL = 'https://ваш-домен/index.html'
.\.venv\Scripts\python.exe run.py
```

В `webapp/config.js` оставьте `apiBaseUrl: ""`. На Linux используйте `python3`, окружение `.venv/bin/python` и соответствующий синтаксис переменных окружения.

### Вариант 2: сохранить GitHub Pages

1. Разместите Python-сервер с HTTPS-доступом.
2. В `webapp/config.js` укажите его адрес **без `/api`**:

```javascript
window.APP_CONFIG = { apiBaseUrl: "https://адрес-сервера" };
```

3. Опубликуйте содержимое папки `webapp` на GitHub Pages: `index.html`, `app.js`, `config.js`, `catalog.json`. Python-файлы и база остаются на сервере.
4. `WEB_APP_URL` по умолчанию сохраняет исходный адрес `https://litvawasi-ops.github.io/my-app/index.html`.
5. Если домен страницы изменился, укажите его в `ALLOWED_ORIGINS`. Допускается несколько адресов через запятую, без путей и без завершающего `/`.

Сервер должен постоянно работать для общих броней и напоминаний. Для проверки доступности предусмотрен адрес `/health`. Сохраняйте файл базы между перезапусками и обновлениями размещения.

Исходный код опубликован в открытом репозитории `CaptainReinor/doklad-bot`. До первого успешного запуска `setup-server.cmd` действующий бот продолжает работать через прежнюю systemd-службу.

## Администрирование

Администраторы по умолчанию: `930703477` и `842525310`. Список можно переопределить переменной `ADMIN_IDS`, перечислив Telegram ID через запятую. Одиночная переменная `ADMIN_ID` по-прежнему поддерживается для совместимости.

В «Кабинете» администратора доступны три раздела: **Управление темами**, **Управление домашкой** и **Управление расписанием**. Домашнее задание содержит предмет из расписания, описание и обязательный срок; его можно добавить, изменить или удалить. Для студента вкладка «Домашка» является справочной и не содержит кнопок действий. В управлении темами задаются предмет, срок, группа, флажки **Общий доклад** и **Несколько выступающих**. Темы конкретной группы скрыты от другой группы. В расписании поле дисциплины предлагает полные существующие названия и допускает ввод новой дисциплины. Если у выбранного предмета один преподаватель, он подставляется автоматически; при нескольких преподавателях поле заполняется вручную. Администратор может оставить поле «Ссылка» пустым или указать полную HTTPS-ссылку на онлайн-занятие. Права на каждое изменение повторно проверяются сервером. Занятую тему удалить нельзя, но её можно перенести в архив или сначала снять бронь студента.

При регистрации группа выбирается строго из `МН-4-25-01` и `МН-4-25-02`. Имя и фамилия принимают только буквы, а также внутренний дефис или апостроф; цифры, HTML, emoji и прочие символы отклоняются браузером и повторно проверяются сервером. Запасная регистрация в чате показывает две кнопки групп.

В чате бота:

| Команда | Действие |
|---|---|
| `/start`, `/app` | Открытие приложения; новый пользователь попадает в кабинет |
| `/register` | Запасная регистрация сообщениями |
| `/cancel` | Отмена незавершённой регистрации |
| `/help` | Список команд |
| `/users` | Список студентов, только администратор |
| `/stats` | Статистика по группам, только администратор |

Четыре прежние записи без описаний удалены. Новые задания создаются администратором и отображаются во вкладке «Домашка». Десять исходных тем отнесены к предмету «Управление программами и портфелями проектов» и группе `МН-4-25-01`; их сроки показываются на карточках докладов и меняются внутри «Управления темами». При обновлении старой базы тема с бронями одной группы автоматически закрепляется за этой группой. Если у темы уже есть брони обеих групп, она сохраняется как общий одиночный доклад и не принимает новые брони, пока администратор не снимет лишнюю.

## Настройки

`config.py` содержит токен бота. Остальные настройки находятся в `settings.py` и могут задаваться переменными окружения:

| Переменная | Значение по умолчанию |
|---|---|
| `WEB_APP_URL` | Исходный адрес GitHub Pages |
| `TELEGRAM_API_BASE` | Пусто; необязательный адрес доверенного HTTPS-прокси Telegram API |
| `ADMIN_IDS` | `930703477,842525310` |
| `DATABASE_PATH` | `schedule.db` рядом с Python-файлами |
| `HOST` | `127.0.0.1` |
| `PORT` | `8080` |
| `ALLOWED_ORIGINS` | `https://litvawasi-ops.github.io` |
| `APP_TIMEZONE` | `Europe/Moscow` |

При размещении в контейнере может потребоваться `HOST=0.0.0.0` и постоянный том для `DATABASE_PATH`. Запускайте один экземпляр polling-бота на этот токен. Если для него уже установлен webhook, программа сообщит об этом при запуске.

Если сеть сервера не пропускает соединения к `api.telegram.org`, бот поддерживает собственный HTTPS-прокси. Код ограниченного Cloudflare Worker находится в `proxy/cloudflare-worker.js`: он обслуживает только текущий числовой ID бота. После публикации Worker задайте `TELEGRAM_API_BASE=https://имя.workers.dev/telegram` в окружении службы. Токен остаётся в `config.py` и в исходный код Worker не записывается; при работе он передаётся через Worker к Telegram по HTTPS.

Исходные темы и расписание находятся в `webapp/catalog.json` и автоматически переносятся в базу. После этого администратор управляет ими из приложения. При переименовании темы связанные бронирования переносятся автоматически. Изменение расписания обнаруживается фоновым обработчиком и сообщается подписанным пользователям.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\ruff.exe check .
```

76 тестов проверяют регистрацию, допустимые группы и имена, команды, необязательный прокси Telegram API, права нескольких администраторов, домашние задания, групповые и общие доклады, нескольких выступающих, управление темами и расписанием, снятие чужой брони, подлинность Telegram-сессии, перенос базы, конкурирующие бронирования, пакетные пользовательские уведомления и дедлайны. Тесты используют вымышленный токен и временные базы.

Дополнительный браузерный тест находится в `tests/browser_smoke.cjs`. Для него нужны Node.js и Playwright 1.62.1 (`npm install --no-save playwright@1.62.1`). На Windows используется Edge; на других системах установите Chromium командой `npx playwright install chromium`.

В первом терминале запустите отдельную тестовую базу:

```powershell
.\.venv\Scripts\python.exe tests/browser_server.py --db browser-test.db --port 8765
```

Во втором:

```powershell
node tests/browser_smoke.cjs
```

Для повторного запуска указывайте новое имя тестовой базы. Если порт занят или зарезервирован Windows, запустите с `--port 0` и передайте показанный адрес через переменную `TEST_BASE_URL`. Тест создаёт снимки и пробную выгрузку в `browser-test-results/`.

## Структура

```text
run.py              совместный запуск
bot.py              команды и регистрация в Telegram
server.py           HTTP API и выдача мини-приложения
auth.py             проверка Telegram initData
service.py          правила, права и действия
database.py         база, миграция, бронирования и очередь уведомлений
notifications.py    напоминания и отправка накопленных уведомлений
catalog.py          чтение учебных данных
settings.py         настройки размещения
config.py           токен Telegram-бота
schedule.db         исходная база
webapp/             интерфейс и учебные данные
tests/              автоматические проверки
```

Для раздельного запуска: `python server.py` и `python bot.py` из одного проекта с одним `DATABASE_PATH`. Команда `python database.py` только подготавливает базу.

## Документация протокола

Используется проверенная сервером сессия Telegram и обычный HTTP API. Метод `sendData` предусмотрен Telegram для кнопок обычной клавиатуры; исходная inline-кнопка работает с другой схемой. Основание: [Telegram Mini Apps — способы запуска и проверка данных](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [pyTelegramBotAPI](https://pytba.readthedocs.io/en/latest/sync_version/index.html).

PDF формируется браузерной библиотекой html2pdf.js; при недоступности её CDN приложение показывает сообщение. Файл содержит изображение таблицы, поэтому поиск по его тексту не поддерживается. В текущей проверке Telegram-события моделировались: окончательный проход через реальный Telegram выполняется после подключения HTTPS-адреса.
