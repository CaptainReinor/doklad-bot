# Результаты проверки проекта

Исправлены ошибки бота, мини-приложения и обмена данными. Дополнительно реализованы темы для конкретной группы и общие темы, несколько выступающих, несколько администраторов, управление темами и расписанием из приложения, предметы докладов, а также снятие чужой брони администратором.

## Найденные проблемы и исправления

| Проблема | Что изменилось |
|---|---|
| Обработчик любого текста был объявлен раньше `/users` и `/stats` и перехватывал эти команды | Команды обрабатываются первыми; введённые команды не попадают в имя или фамилию |
| Inline-кнопка приложения использовалась вместе с неподходящим для неё `sendData` | Добавлен серверный HTTP API с проверкой Telegram-сессии |
| Приложение отправляло объект темы, а SQLite ожидала строку | Единый проверяемый формат действий, поддержка прежнего объекта темы |
| Браузер подтверждал бронь до проверки сервером | Успех отображается после подтверждения; при ошибке загружается реальное состояние |
| Брони и личные данные существовали преимущественно в localStorage одного браузера | Общая база для бота и приложения, загрузка профиля и броней с сервера |
| Для доклада нельзя было задать аудиторию и число выступающих | Администратор выбирает группу или общий доклад и при необходимости разрешает нескольких выступающих; сервер скрывает чужие темы и проверяет каждую бронь |
| Отмена, регистрация и правка профиля из приложения не имели соответствующих обработчиков | Добавлены все используемые действия, проверка владельца и обязательной группы |
| Изменение имени или группы могло оставить прежние сведения о владельце брони | Профиль и его брони обновляются одной транзакцией; конфликт откатывает изменение |
| Настройки уведомлений использовали разные имена действий и терялись при перезапуске | Общий формат, хранение в SQLite, восстановление настроек и очереди отправки |
| Разница дат считалась с учётом текущего часа; напоминания пропускались или повторялись | Сравнение календарных дат, московский часовой пояс, сохранение факта отправки |
| Даты в коде бота расходились с датами в приложении | Используются исходные даты мини-приложения; сроки заданий и докладов редактируются внутри управления темами без отдельного раздела |
| Первый проход напоминаний откладывался на шесть часов | Проверка начинается сразу, затем повторяется раз в минуту |
| Устаревший или отменённый доклад мог оставаться в очереди напоминаний | Перед отправкой повторно проверяется актуальный срок и наличие брони |
| Сегодняшние занятия считались проведёнными с полуночи | Статус меняется по времени окончания занятия |
| Прошедшие занятия загромождали основную ленту | По умолчанию показаны ближайшие занятия; прошлые даты вынесены в отдельный раздел и отсортированы от новых к старым |
| Темы и расписание можно было менять только в файлах | Данные перенесены в SQLite; администратор добавляет, редактирует, архивирует, восстанавливает и удаляет записи из кабинета |
| У темы доклада не было предмета | При создании и редактировании указывается предмет; интерфейс предлагает дисциплины из расписания |
| Темы разных дисциплин находились в одном длинном списке | Добавлены фильтры по предметам, короткие подписи и отдельный список тем без назначенного предмета |
| В расписании нельзя было открыть онлайн-занятие | Администратор может указать необязательную HTTPS-ссылку; кнопка подключения появляется только у такого занятия |
| При добавлении занятия приходилось повторно вводить преподавателя | После выбора дисциплины единственный связанный преподаватель подставляется автоматически |
| Администратор не мог исправить ошибочную бронь студента | В управлении темами показываются владелец и группа, добавлена кнопка снятия брони |
| Новый пользователь начинал регистрацию сообщениями | `/start` ведёт в приложение и сразу открывает форму регистрации в кабинете; `/register` оставлен запасным вариантом |
| При регистрации можно было написать произвольную группу | В приложении группа выбирается только из МН-4-25-01 и МН-4-25-02; сервер отклоняет подменённые значения |
| В имени и фамилии принимались цифры, emoji и случайные символы | Добавлена клиентская и серверная проверка: допускаются буквы, внутренний дефис и апостроф |
| Старые учебные задания содержали только название предмета и непонятный срок | Добавлена отдельная вкладка «Домашка»; прежние записи удалены, администратор создаёт задания с предметом, описанием и сроком |
| Управление домашними заданиями было смешано с темами докладов | В кабинете появился отдельный редактор домашки с добавлением, изменением и удалением; студентам доступен только просмотр |
| Московский VPS периодически теряет исходящий маршрут к Telegram API | Добавлена настройка доверенного HTTPS-прокси и подготовлен ограниченный Cloudflare Worker без токена в исходном коде |
| Мобильное приложение могло бесконечно ждать Telegram SDK, PDF-модуль или шрифт со стороннего CDN | Telegram SDK и PDF-модуль обслуживаются тем же сервером, внешняя загрузка Google Fonts удалена |
| Строка подключения к базе зависела от папки запуска | База привязана к расположению проекта или к заданному `DATABASE_PATH` |
| Регистрация использовала пользовательский текст в Markdown без обработки | Проверка ввода, обычный текст в сообщениях, безопасное отображение в HTML |
| Вкладка «Очередь» показывала число броней как число людей | Общий список «Бронирования», группы и число уникальных студентов |
| Счётчик «Забронировано» отражал только темы текущего пользователя | Верхняя статистика и очередь считают уникальные занятые темы; личные темы показываются отдельно, а `/stats` разделяет темы и выступающих |
| Тема с несколькими выступающими одновременно попадала в «занято» и «доступно» | Счётчик свободных тем равен общему количеству минус уникальные занятые темы; присоединение к групповому докладу по-прежнему разрешено кнопкой |
| Редактирование десяти тем отправляло каждому студенту десять сообщений | Уведомления о редактировании, сроках, архивировании, удалении и бронировании тем отключены; новые темы собираются в одну подборку через минуту после последнего добавления и отправляются только подходящей группе |
| В настройках были пересекающиеся уведомления о темах и общем списке броней | Оставлены три независимых переключателя: домашка, новые темы докладов и изменения расписания; напоминания о сроках подчиняются переключателю соответствующего раздела |
| При проверке PDF обнаружены пустые страницы и обрезка содержимого | Отдельная табличная разметка для экспорта, исправлены захват и переносы строк |

## Проверено

- 76 автоматических тестов прошли.
- 13 сценариев браузерной проверки прошли на тестовой серверной части; ошибок JavaScript не было.
- 12 одновременных заявок на одиночную тему создали ровно одну бронь; отдельно проверены общие доклады и несколько выступающих одной группы.
- Проверены защита административных действий, неподлинная и просроченная сессия, отказ сервера, сохранность данных после перезагрузки и восстановления соединения.
- Проверено отображение на ширине 320, 390 и 1280 пикселей.
- Проверена непустая PDF-выгрузка текущего фильтра расписания без ошибок JavaScript.
- В `config.py` установлен выданный пользователем новый токен.
- Исходная `schedule.db` также сохранена побайтово. На её отдельной копии проверена миграция: все три зарегистрированных пользователя сохранены, проверка целостности SQLite прошла.
- Исходное расписание и темы сохранены; десяти существующим темам автоматически назначается предмет «Управление программами и портфелями проектов». Четыре прежние записи заданий удалены по запросу пользователя.
- Проверка Python-кода и синтаксиса JavaScript прошла.

## Что нужно для запуска

Проект готов к настройке размещения по `README.md`. Требуется доступный HTTPS-сервер и его адрес. Если интерфейс остаётся на GitHub Pages, адрес серверной части задаётся в `webapp/config.js`.

Автоматические проверки не отправляют сообщения в Telegram. Реальный запуск выполняется на выделенном пользователем сервере; окончательную проверку интерфейса нужно пройти через кнопку нового бота после загрузки этой версии.

Данные расписания не сверялись с внешним расписанием вуза: использованы материалы вашего архива. Даты докладов сохранены из исходного интерфейса и редактируются администратором в управлении темами.

Использованы [официальная документация Telegram Mini Apps](https://core.telegram.org/bots/webapps) и [документация pyTelegramBotAPI](https://pytba.readthedocs.io/en/latest/sync_version/index.html).
